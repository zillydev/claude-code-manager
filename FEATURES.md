# claude-code-manager — Features

A tool to browse, search, edit, compact, harvest, and resume Claude Code session `.jsonl` files. A **Tauri 2 + React 19 desktop app** over a reusable Rust core (`claude-code-manager-core`).

> **Maintenance:** update this file **on the feature branch** as the last step before merging a NEW capability, so the entry lands in the same commit as the feature — fixes and refinements need no entry. Each entry links to its design spec in `docs/superpowers/specs/` (and plan in `docs/superpowers/plans/`) for the full rationale. Per-feature specs are the source of truth for *why/how*; this file is the index of *what exists now*.

## Architecture

- **Cargo workspace:** `crates/core` (lib — parsing/render/store/surgery; deliberately front-end agnostic so another UI can be added later), `crates/app` (Tauri 2 + React/TS/Vite/Tailwind — the interface), `crates/cli` (the `claude-code-manager` binary: `surgery` subcommands, driven by the skills).
- Operates on `~/.claude/projects/<encoded-cwd>/<uuid>.jsonl` — one JSON object per line, linked into a tree by `parentUuid`.
- **Copy-on-edit safety:** every fork/edit/delete/surgery writes a NEW session file; originals are never mutated (sole exception: rename, which appends a `custom-title` line in place).
- Run: `make dev` (`scripts/dev.sh`: Vite + debug app, relaunchable) · `make build` · `make test` · `make print` (CLI smoke test).

## Browsing & viewing

- **Sidebar tabs (Obsidian-style)** — an icon strip atop the sidebar: 🗂 Sessions (⌘1) · ⚑ Bookmarks (⌘2) · 🔍 Find (⌘3, = ⌘⇧F incl. focus). Panes keep their results/previews across switches; clicking a hit opens the session while the pane stays. → `2026-08-06-sidebar-tabs-design`

- Sessions list — project, title, tokens, updated (time of the last real conversation turn); project / tag / time filters — one themed menu each (type-to-filter, scrolling, ↑/↓/Enter, selected pinned to top; projects grouped by name, expanding to directories only on collisions; time behind a clock icon; one ✕ clears all); sort; sidebar resize/collapse. → `2026-05-23-claude-code-manager-tui-design`, `2026-05-24-webui-design`, `2026-06-21-unified-project-selector-design`
- **Right-click menus** — WKWebView's own menu (whose only item was Reload) is suppressed app-wide except in editable fields, where the native Cut/Copy/Paste still belongs. A transcript turn offers Fork from here / Bookmark, a sidebar row Rename / Tags… / Note… / Delete — the same actions as their ⋯ menus, without hunting for the hover button. The menu flips at viewport edges and dismisses on Esc, click, scroll, or window blur.
- **Chat-style sides** — user messages (and slash commands) sit on the **right** in a bordered surface bubble (`max-w-75%`); assistant turns stay full-width on the left.
- **`!` bash-mode blocks** — a shell command run from Claude Code (`<bash-input>` plus a following `<bash-stdout>`/`<bash-stderr>` message) renders as one terminal-style block: `$ command` with its output beneath (stderr in red), HTML entities undone. Display-only, like slash-command turns.
- **Queued messages render** — a message typed while the agent is running (a `queued_command` attachment, no ordinary user line) renders as a view-only user turn.
- **Summarized reasoning renders** — Claude Code's `· summarized` line (a short summary of the reasoning, stored as a text-bearing `thinking` block; real thinking is persisted empty, and from 2.1.263 the signature tags the kind) shows as a normal prose line with a dim `· summarized` suffix, and is searchable. Real thinking stays hidden.
- **API errors render** — Claude Code records a failure ("Prompt is too long", "API Error: 529 Overloaded") as a synthetic assistant line the transcript otherwise hides; it now shows as its own ⚠ turn, so a session that stops mid-reply says why. Kept in compact mode, where it closes the reply it interrupted.
- **Syntax-highlighted code blocks** — rehype-highlight on explicitly-tagged fences, GitHub syntax palette per theme.
- **Bash calls render as shell snippets** — the script as real lines (highlighted as bash, parsed whole so heredocs and quoted blocks survive), with `description` / `timeout` / background as dim `#` comments above it.
- **Questions render as cards** — an `AskUserQuestion` tool call shows the question (with its short header) and its options rather than JSON, and reads the tool result to accent the option that was chosen; a malformed call falls back to JSON.
- **File edits render as diffs** — `Edit`/`Write`/`MultiEdit` tool calls show `-`/`+` lines (LCS line diff) instead of `\n`-escaped JSON, matching what Claude Code prints in the terminal: syntax-highlighted per the file's extension (each side highlighted whole, so multi-line strings/comments survive) with added/removed lines tinted. The diff text is the same string the find bar matches against, so a hit inside a collapsed edit still paints correctly when it expands. Other tools keep the JSON view.
- **MCP output prettified** — `mcp__server__tool` renders as `server · tool`, and single-line JSON results pretty-print (non-JSON/huge payloads untouched).
- **Inline images** — images attached to a prompt show under the user bubble; images a tool returned (e.g. browser screenshots) show inside the expanded tool result. Thumbnails; click opens a Discord-style lightbox (centred over a dimmed backdrop, Esc/backdrop-click closes).
- Transcript rendering — consecutive assistant turns merged, **GFM** markdown (react-markdown + `remark-gfm` + `@tailwindcss/typography`: tables, strikethrough, task-lists; inline code without decorative backticks), tool calls with full input on expand, synthetic turns skipped. Slash-command invocations (e.g. `/deploy-gateway`) render as a compact command line; the injected skill body and `<local-command-…>` machinery stay hidden. Explanatory-style `★ Insight` blocks render as a terminal-style callout (accent rules + markdown body) instead of collapsing into inline-code pills.
- **Jump to top / latest** — ↑ and ↓ buttons stacked at the transcript's bottom-right, each shown only when useful (↑ hidden at the top, ↓ hidden while pinned to the bottom). ↓ re-pins tail-follow as well as scrolling, so live turns resume following.
- Session info panel — token cost, per-turn model, git branch, cwd.
- **Compact** toggle — every prompt plus the first and last turn of each reply, so the tool-churn in the middle collapses (replies close at the next prompt, at a task notification, and at the end of the transcript). Plus a **Details** toggle — both persisted across restarts.
- **Pre-compaction history** — renders all conversation trees in a compacted file with `── segment k/N · pre-compaction|active ──` dividers; pre-compaction turns are view-only (only the active tree is editable). → `2026-06-06-pre-compaction-history-design`
- **Rewound branches** — a rewind or an edit leaves its abandoned branch in the session file, while the transcript draws one path per tree, so those messages are on no screen (5% of user messages global find could return, on a 213-session corpus). A find result landing on one now says so and offers **Show this branch**: the session re-renders along the path through that message and scrolls to it, with a banner back to the current branch. The branch view is frozen — new turns belong to the branch you left, so it doesn't follow the live tail — and its turns are marked non-editable, like pre-compaction ones.

## Search

- **In-session find (⌘F)** — a Zed-style bar between the session header and the transcript: query (Enter/⇧Enter step, Esc closes, ⌘G/⌘⇧G work transcript-focused, a transcript text selection seeds the query), Aa/whole-word/regex toggles, ⚒ "include tool calls & results" (matches in collapsed bodies count and auto-expand on navigation; reveals reset when the bar closes or the toggle turns off), ‹ › with an editable n of n/N (type a number + Enter jumps), ↗ hands the query to the global find pinned to the session, ✕. Matches highlight in place (an amber tint; the active match a solid orange fill with its own text colour, and its ruler mark orange too) and an overview ruler in the scroll gutter marks every match's position; toggles persist. Counts occurrences (the global tab counts messages). → `2026-08-18-in-session-find-bar-design`
- **Global find (⌘⇧F / sidebar 🔍 tab)** — a Discord-style search pane across ALL sessions (cards carry up to 3 excerpt windows around matches — merged when adjacent, " … "-joined otherwise — plus a ×N total-occurrence badge; one card per message, while the ⌘F bar counts occurrences; a message with no text to excerpt — a bare tool call, as `tool:` queries return — shows the call instead, tool name styled as in the transcript plus its key input: Bash's command, AskUserQuestion's question, a file path kept to its tail; bookmark rows do the same): free text + operators `in:` `from:` `before:` `after:` `tag:` `is:bookmarked` `tool:` `has:link` `session:` (quoted values ok; unknown `foo:bar` is literal text; malformed dates error inline). Enter to search; a ✕ in the field clears the query, its results and any in-flight search; live value autocomplete for `in:`/`tag:`/`from:`/`is:` from memory, and for `tool:` every tool your sessions have called, most used first and matched anywhere in the name (counted during discovery's existing parse); between tokens the focused input shows an Obsidian-style **Search options** legend, narrowing mid-word to the operators that word could become (click replaces the word; every pick brings it back so operators chain, until Enter); a bare `before:`/`after:` shows a themed **MiniCalendar** (+ optional hh:mm; typed dates accept `yyyy-mm-dd[Thh:mm]`, local time). Session-level narrowing happens frontend-side (metadata lives there) down to a candidate file list; `core::search_messages` walks only those, confirms text in conversation blocks (never tool payloads), and caps at 200 with a truncation notice. Results are **Discord-shaped**: a `N`/`N+` count bar, strictly newest-first order across all sessions with a `#` session header re-appearing on session change, roomy cards (role · time, transcript-matching type, run term highlighted amber via `splitHighlight`), and **Load more** paging past the 200-hit cap; click opens the session scrolled to + flashing the match, and hands the free text to the ⌘F bar starting on the occurrence inside that message (escaped when the saved regex toggle is on; the other toggles are left alone). The sidebar box does **name/project filtering only** — one content search, one place. → `2026-08-05-global-find-design`
- Sidebar box (names only): matches a session's project and **both** its names — the local alias and claude's auto-title, since a renamed row shows both. (Sorting by Title uses the alias when set.)

## Organization

- **Session organization** — claude-code-manager-local metadata over sessions, in a separate `session-meta.json` (same dir/env as the config; claude's `.jsonl` is never touched). Global **tags** (a `name+color` registry; colored chips on rows; a per-session Tags… editor with autocomplete; a sidebar any-of **tag filter** (inherited by a newly created session); a **Manage tags…** window to recolor/rename/delete/**archive** — an archived tag keeps every session it's on but leaves the choosers: the sidebar tag-filter menu, the Tags… editor suggestions, and the find tab's `tag:` autocomplete; each offers a temporary **Show archived** to reveal them, and Manage tags lists them in an Archived section with unarchive), a **local alias** (a rename that is NOT claude's `custom-title` — so no live-terminal desync; shown as the row's primary title with claude's auto-name dim beneath), and a per-session **note** (`✎` on rows, full text under the details panel). A session derived by copy-on-edit (fork / edit / delete) inherits the source's tags — tags only, not the alias (which would duplicate a name) or note. Live + broadcast across windows; dangling tags self-heal on load. → `2026-07-06-session-organization-design`

## Bookmarks

- **Message bookmarks** — flag any user/assistant message from its ⋯ menu (metadata-only, so pre-compaction turns work too); stored as the turn's head uuid in `session-meta.json` (`bookmarks: [uuid]`), live across windows. An accent **⚑** marks bookmarked turns; the sidebar's **⚑ tab** shows the all-sessions browser — grouped by session, snippets + times via `message_previews` — where a click opens that session scrolled to the message (instantly when it's already open). Query them too: `is:bookmarked` in the find tab. Derived sessions do NOT inherit bookmarks. → `2026-08-05-message-bookmarks-design`

## Editing & surgery

- **Fork from here** — copies the session file **as-is** up to the chosen message (file order), changing only what session identity requires: a new `sessionId` on every line, `forkedFrom` on the cut line, a fresh `last-prompt`, and — only if the copy would otherwise end on an unanswered `tool_use` — one synthesized `tool_result`. Nothing is flattened, trimmed, or re-uuid'd, so abandoned rewind branches and pre-compaction segments (including the `isCompactSummary` bridge) come along. The cut extends over the `tool_result` lines answering it, so a call is never separated from its result. → `2026-05-30-session-editor-design`
- **Edit / delete a message** — REMOVED pending a reimplementation (UI, `useEditor` handlers, and the `commit_session` / `delete_message` / `open_for_edit` commands are gone). `core::edit::commit` — the flatten/relink/repair pipeline — stays, since surgery uses it, and the renderer still emits `editable` / `edit_uuid` for the rebuild. → `2026-05-30-session-editor-design`
- **Delete a session** (trash with restore).
- **`session-surgery` skill + CLI** (`surgery extract` / `rewrite`) — summarize or prune a turn-snapped message range → a new resumable session (timestamps backfilled so `claude --resume` accepts it). `--from/--to` accept a uuid **prefix**. → `2026-05-30-session-surgery-skill-design`, `2026-06-18-surgery-rewrite-parity-design`

## Lineage

- **Linked / forked sessions** — sidebar badges (`⮌ from …`, `⑂ N`) + a transcript banner, from CC's `forkedFrom`. → `2026-06-14-linked-sessions-design`
- **Cross-session copy lineage** — inferred from shared message-uuid overlap (handles background-restart / manual-`/compact` copies that split a session across files); bidirectional badges + banner. → `2026-06-17-compaction-lineage-design`
- **Inline "forked from here" markers** — at the deepest copied message (the real branch point) in the parent session. → `2026-06-17-fork-point-markers-design`
- **Lineage tree** — on-demand overlay showing a session's whole fork/copy family as an indented tree (`◀ origin` root, `⑂ forked at "…"` / `⧉ copied · N shared` edges, `● you`), opened from the transcript `⑂ Tree` button or the clickable sidebar `⑂ N`/`⧉ N` badges; click a node to open it. A branch label links to the **parent session scrolled to + flashing the branch message** (matched across merged assistant turns); it's plain text with an explanatory tooltip when that point sits on an edited-away branch the transcript doesn't render. → `2026-06-24-lineage-tree-design`

## Harvest (read-only session mining)

- **`session-harvest` skill + `surgery extract --outline [--all-segments]`** — outline-first navigation (compact one-line-per-turn map with 8-char short ids + salient tool args, `· compaction summary` tags), drill down by uuid-prefix range, classify spans → produce a **skill / kb entry / script / summary**. Ranks candidates by reuse over novelty; checks for an already-written distillation before proposing kb/summary. Read-only re sessions. → `2026-06-18-session-harvest-design`, `-harvest-all-segments-`, `-sharpen-harvest-tooling-`
- Outline & drill-down clean machinery: command echoes → `/cmd`, task-notifications collapsed, slash-command/empty turns skipped, embedded skill prompts elided. → `2026-06-18-clean-noisy-messages-design`, `-elide-skill-prompts-design`

## Multi-window

- **Multiple windows** (⌘N + native menu) — one per macOS Space; per-window live-tail isolation (watcher + events scoped by window label). → `2026-06-14-multi-window-design`
- **One terminal per session, app-wide** — the PTY pool is keyed by session (not window), so a session opened in the terminal of one window can't be opened in another; the second window shows "already open in another window" + a **Switch to it** button. Prevents two `claude --resume` processes corrupting one `.jsonl`. → `2026-06-22-terminal-corruption-guard-design`
- **Shared state across windows** — a single backend poller computes discovery + the activity scan once (app-globally, single-flight cache) and broadcasts `activity-updated` / `sessions-changed` to every window, so N windows cost ≈ one; windows listen instead of each polling. Unread (`lastViewed`) syncs across windows. → `2026-06-22-shared-state-poller-design`

## Embedded terminal

- **Manager | Terminal tabs** in the session pane (sidebar always visible). The Terminal tab runs the real interactive `claude --resume <open session>` in a PTY (xterm.js + `portable-pty`) — full TUI, exactly like Ghostty. One persistent terminal per session, **spawned lazily** only when a session's terminal first becomes visible; uses the user's bypass alias (`claude-tracked --dangerously-skip-permissions`). The Manager/Terminal toggle lives in the session header; **⌘E** toggles tabs, **⌘B** the sidebar. A **green dot** on the Terminal tab button marks a live terminal for the open session; a hover-**✕** closes it (kills `claude`, leaving the pane's `[process exited]` + Restart). The terminal is **themed with the app** (palette + GitHub ANSI set, re-applied on theme change); set claude's own theme to **`auto`** (`/theme`) and it follows the app theme too (it queries the terminal background via OSC 11). → `2026-06-19-terminal-tab-design`, `2026-07-08-close-terminal-session-design`
- **New session** — a `+ New` sidebar popover (paste a directory path, or create in the selected project's directory) spawns a fresh `claude --session-id` in that cwd. Manager and Terminal share one open session, so they never diverge; the new session surfaces in the sidebar/Manager once claude writes the first turn (polled, since the file doesn't exist until then). → `2026-06-21-new-session-design`
- **Asks before stopping work** — closing a window (⌘W / close button) or quitting (⌘Q) kills the `claude` processes its terminals run; when any of those sessions shows the running dot, a dialog lists them first (Cancel focused; Esc cancels), while idle terminals close silently since their sessions resume from the file. The backend picks the affected terminals (the window's own, or all for a quit) and the window decides with the sidebar's own `deriveStatus` inputs. ⌘Q is a custom menu item because tao handles `applicationWillTerminate` but not `applicationShouldTerminate`, so the predefined Quit can't be cancelled; quitting from the Dock or at logout still skips the check.

## Live tail & scrolling

- Open sessions **live-tail** their file — new turns stream in (so a session being written, incl. by the embedded terminal, updates in real time).
- **Tail-follow** — auto-scroll to a new turn only when the user is pinned to the bottom; a scrolled-up reader is left alone. Scroll-to-bottom restored when returning from the Terminal tab.

## Customization

- **Settings panel** (`⚙` in the sidebar header, or `⌘,`) backed by a JSON config file — location resolves `$CLAUDE_CODE_MANAGER_CONFIG_DIR` → `$XDG_CONFIG_HOME/claude-code-manager` → `~/.config/claude-code-manager` (`config.json`). Covers **theme** (GitHub Dark / Light), **typography** (font size 12–18 via the root rem; a `compact` density that shrinks Tailwind's `--spacing` token globally; UI + Mono font choices — presets or a custom family, the mono font also re-applied to the live terminal), and **behavior** (compact / details / sidebar width + collapsed are set-and-stick config; launch-only defaults for the tab and for the sidebar's **project filter** — picked from the same searchable project menu the sidebar uses, and ignored at launch if that project no longer has sessions). Changes apply live and broadcast to every window. An **About** section shows the running build's version (read from the bundle) and opens the repo, that version's release notes, and the new-issue page in the browser. → `2026-06-28-ui-customization-design`

## Feedback

- **Inline loading indicators** — a shared `<Spinner>` atom marks every async action while it runs: fork, sidebar delete / rename / new-session, the terminal's "Starting claude…" overlay, session-open and search. → `2026-06-21-loading-indicators-design`
- **Session status indicators** — sidebar dots driven by a lightweight focus-gated poll (`session_activity`, tail-reads recent files): a green pulsing dot when claude is mid-turn (steady through thinking pauses — keyed on `awaiting_input` turn-completeness, not write recency), and an accent dot + bold title for **unread** (your turn — a completed reply or a turn parked on `AskUserQuestion` / `ExitPlanMode` — newer than when you last opened it). → `2026-06-22-session-indicators-design`

## Integrations

- **Session status publishing** (opt-in — Settings → Integrations) — writes `session-status.json` in the config dir for other tools (status bars, notifiers): per-session `running`/`unread`/`idle` plus the raw `awaiting_input`/`last_event_at`, `cwd`, `title`, and the macOS window id (= yabai's id, via the PTY owner's `NSWindow.windowNumber`) for sessions running in a ccm terminal tab. Derived from the same poller as the sidebar dots, so it self-corrects. Atomic replace, written only on change, removed when disabled or on exit. Dev builds write `session-status.dev.json` so `make dev` never fights the installed app over it. → `2026-08-21-session-status-publishing-design`
- **Precise status via Claude Code hooks** (opt-in — Settings → Integrations) — installs a relay into `~/.claude/settings.json` (idempotent, exact-inverse uninstall, one-time `settings.json.ccm-backup`; the user's own hooks untouched) so claude reports its state itself: `UserPromptSubmit` ⇒ running, `PreToolUse`/`PermissionRequest` on `AskUserQuestion`/`ExitPlanMode` ⇒ needs you the moment the card appears, `Stop` ⇒ your turn within seconds. The relay appends to `hook-events.ndjson` (self-rotating); the poller tails and folds it into a per-session phase that **outranks inference only while at least as fresh as the session file** — interrupts and kills fire no hook, so the file-based derivation reclaims stranded state on its next line, and unhosted hook-"running" decays on the usual staleness clock. Without the toggle, everything falls back to the file + terminal-attribution inference.

## Conventions & dev notes

- Workflow per feature: **brainstorm → spec → plan → execute → finish → user-directed merge** (squash into `main` — one commit per feature — then `git branch -D`; tests green first). Pushing to the remote is a separate, explicit ask.
- **Never launch the app from automation** — the user keeps it open across Spaces; nothing in `make dev` watches Rust files (frontend hot-reloads via Vite).
- **Dev Rebuild & Relaunch** (⌘⇧R, Develop menu — `make dev` only) — rebuilds while the windows stay up; on success relaunches via the `scripts/dev.sh` loop (exit code 75) restoring every window's frame, open session and sidebar tab; on failure a banner shows the compiler errors with Retry and the old build keeps running. → `2026-09-14-dev-rebuild-relaunch-design`
- `~/.claude/settings.json` has `cleanupPeriodDays: 36500` so sessions aren't auto-pruned.
- Skills live in `skills/` (`session-surgery`, `session-harvest`).
- **App icon:** `crates/app/icons/icon.svg` is the source (dark squircle, mono "ccm" wordmark, Apple icon-grid margin baked in). Regenerate the PNG/`.icns`/`.ico` set with `cargo tauri icon <1024px raster>` from `crates/app/` — it overwrites `icons/`, then drop the mobile/Windows-Store variants it also emits.
- **App name:** `productName` in `tauri.conf.json` is "Claude Code Manager" (Dock/Finder/⌘-Tab label and the `.app` filename; window title matches). The bundle `identifier` and config dir stay `claude-code-manager` — those are the stable ids macOS keys permissions on. Dev runs are unbundled, and LaunchServices names those after the binary file, so `src/dock_name.rs` sets the LS display name at startup (JDK `-Xdock:name` technique, `dlsym`-resolved, macOS debug builds only).
