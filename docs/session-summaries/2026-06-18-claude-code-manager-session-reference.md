## 1. Project shape

**What it is:** a tool to manage Claude Code session `.jsonl` files. Two front-ends over one shared Rust core. Sessions live at `~/.claude/projects/<encoded-cwd>/<uuid>.jsonl` (cwd encoded by replacing `/` with `-`), one JSON object per line, linked via `parentUuid` into a tree.

**Cargo workspace** (`Cargo.toml`, `resolver = "2"`, `[profile.release] lto="thin", codegen-units=1`):
- `crates/core` — `claude-code-manager-core` (lib). Modules:
  - `session/event.rs` — typed jsonl event model (`UserEvent`, `AssistantEvent`, `Event` enum; event kinds: user, assistant, system, attachment, summary, ai-title, custom-title, agent-name, last-prompt (carries `leafUuid`+`lastPrompt`), permission-mode, file-history-snapshot, mode). Accessors `forked_from_session()`, `forked_from_message()`.
  - `session/raw.rs` — `RawLine { value, uuid, parent, kind }`; `read_raw`, `resolve_leaf` (leaf = last uuid line = append-only tip), `path_to(lines, leaf)` (walk parent to any node's tree root), `active_path` (delegates to `path_to(resolve_leaf)`), `first_cwd` (launch cwd = first cwd in file order), `segments(lines) -> Vec<Vec<&RawLine>>` (raw-line mirror of `tree::segments`).
  - `session/tree.rs` — `segments(events)` (group by tree root via memoized `root_of`; active tree last).
  - `session/render.rs` — `RenderedSession`, `RenderedTurn` (User/Assistant carry `edit_index`, `fork_index`, `edit_uuid`, `fork_uuid`, `editable`; `Compaction { messages_before }` variant; `TaskNotification` variant). Merges consecutive assistant events; skips synthetic. `render_session` loops `tree::segments`, inserts dividers, marks only the active (last) segment editable.
  - `session/summary.rs` — `SessionSummary` (fields incl. `forked_from`, `copied_from`, `copied_overlap`, `forked_from_message`, `copied_from_message`). Title fallback = custom-title (last-wins) → last user message (NOT ai-title).
  - `session/edit.rs` — **the central session-file writer** (`commit()` pipeline): filters to message lines, repairs tool-pairing, backfills timestamps (step 2.5), regenerates uuid/parentUuid/sessionId/cwd/gitBranch, writes `forkedFrom`, appends last-prompt, writes a NEW file. Also `append_custom_title(path, title)` (rename — the one in-place mutation).
  - `session/surgery.rs` — `extract`, `rewrite`, `snap_range`, `resolve_session_path`, `render_outline`, `tool_salient`, `ellipsis`, `RewriteMode {Prune,Summary}`, `RewriteOutcome`.
  - `session/display.rs` — (new) `command_label`, `parse_task_notification`+`TaskNote`, `one_line`, `extract_tag` (noisy-message parsing).
  - `session/parse.rs` — `parse_tail` (incremental live-tail parsing).
  - `store/mod.rs` — `discover`, `open_session`, `trash_session` (→ `~/.claude/.trash/claude-code-manager/<stem>.<unix-ts>.jsonl` + `.trashinfo`), `search_sessions`.

  - `store/lineage.rs` — (new) `SessionUuids`, `copy_lineage` (shared-uuid copy-ancestry inference).

- `crates/tui` — `claude-code-manager-tui` (ratatui binary `claude-code-manager`). Files: `main.rs` (also hosts the `surgery` CLI: `SurgeryOp::Extract`/`Rewrite`), `app.rs`, `ui/{list_view,transcript_view,theme,mod}.rs`.
- `crates/webui` — `claude-code-manager-webui` (Tauri 2 + React 19 + TS + Vite + Tailwind v4 + @tailwindcss/typography). **Session model concepts:**
- **Active path** = walk `parentUuid` back from `resolve_leaf` (last uuid line, the append-only tip), reverse. For a compacted file this is only the post-compaction tree.
- **Segments / multi-tree:** auto-compaction (and manual `/compact`) **re-roots the tree** — CC writes a NEW null-parent root (`system`, `subtype:"compact_boundary"`) into the SAME file, then an `isCompactSummary:true` user message ("This session is being continued from a previous conversation…"), then continues. N compactions ⇒ N+1 disconnected trees in one file. `tree::segments`/`raw::segments` group these; the active tree is rendered last with `── segment k/N · pre-compaction|active ──` dividers.
- **Copy-on-edit safety model:** fork/edit/delete/surgery all write a NEW session file (new uuid) via `edit::commit()`; originals are NEVER mutated — the sole deliberate exception is **rename**, which appends a `custom-title` line in place (`append_custom_title`).
- **`forkedFrom` field:** CC records `{"sessionId","messageUuid"}` on each copied line for `/branch` and `--fork-session`. Read for free for CC forks; written by our `commit()` for our forks.
- **Tool-pairing invariant:** every assistant `tool_use` needs a following user `tool_result` with matching `tool_use_id`; repair synthesizes placeholders / drops orphans.
- **Tauri camelCase param conversion** (filePath, editUuid, forkUuid, newTitle, etc.).

**Build/run (`Makefile`):** `make tui`, `make webui` (= `cd crates/webui && cargo tauri dev --no-watch`), `make build` (npm install+build frontend, then `cargo build --release`), `make test` (`cargo test`), `make print`, `make clean`.

**Workflow convention (used for nearly every feature):** superpowers `brainstorming` → write spec to `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` (committed) → `writing-plans` → plan to `docs/superpowers/plans/` → `executing-plans` (inline) or `subagent-driven-development` (implementer + spec-review + code-quality-review per task) → `finishing-a-development-branch` → **user-directed merge** (`--no-ff` into `main`, verify tests, delete branch). Branch per feature.

## 3. Durable invariants & conventions
- **Copy-on-edit:** every fork/edit/delete/surgery writes a NEW session file; originals never mutated. Sole exception: **rename** (`append_custom_title`, in-place additive).
- **NEVER launch the webui yourself** (`make webui` / `cargo tauri dev`). The user keeps it open across macOS Spaces; a (re)launch pops the window into their face. Hand the user the manual GUI steps. (`never-launch-webui-myself.md`.)
- **`make webui` uses `--no-watch`** — the dev app does NOT auto-restart on Rust edits; to pick up Rust changes, the user stops + re-runs. Frontend edits hot-reload via Vite HMR. (`webui-dev-no-watch.md`.)
- **surgery vs harvest:** surgery = compress a session to resume it (rewrites → new file). harvest = read a session, emit reusable artifacts (read-only re sessions; only writes new artifact files; confirm every write).
- **`--all-segments` is opt-in** (default OFF) so surgery's behavior is unchanged; harvest passes it. A `--from/--to` range must stay within one tree.
- **User directs all merges** ("merge"/"merge to main") — never merge without explicit instruction. Commit only when asked. Merges are `--no-ff` into `main`, verify tests, delete branch.
- **`cleanupPeriodDays: 36500`** is set in `~/.claude/settings.json` so sessions aren't auto-pruned.
- **CSS Custom Highlight API** for find; `::highlight()` rules served raw from `index.html` (lightningcss strips them).
- Workflow: brainstorm → spec → plan → execute (inline or subagent) → finish → user merge. Specs in `docs/superpowers/specs/`, plans in `docs/superpowers/plans/`.

## 5. session-harvest skill performance (from dogfooding this summary)
The summary above was produced by a fresh, context-free subagent using `session-harvest` on this very session — a deliberate test. Findings:
- **Outline-first → drill-down worked well** on a 3-segment / ~360-turn session; the agent never read the raw ~6.8k-line jsonl. The two-line salient-args format made the tool-call sequence scannable enough to identify every feature arc and its merge from the outline alone; the segment dividers framed the trees; the in-file compaction summaries (segments 1–2) let the agent drill only segment 3 in detail.
- **Outline uuid fidelity is correct** — verified all 363 outline header uuids are exact, real file uuids (0 missing). The subagent's report of "corrupted uuids" was its own hex-transcription error, not a render bug.
- **Real friction → future enhancements:** (a) long uuids are error-prone for an agent to copy into `--from/--to` — consider accepting the `#N` ordinal or a uuid prefix as a range target; (b) the `--from/--to` "not in any conversation tree" / "different conversation trees" errors could name the offending uuid's segment; (c) tag compaction-summary turns in the outline (e.g. `(compaction summary)`) since they're the densest, most valuable content to read first.
